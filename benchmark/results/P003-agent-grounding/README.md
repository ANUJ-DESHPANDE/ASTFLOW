# P003 investigation grounding

Decision: **PASS WITH DOCUMENTED LIMITATION**. The product uses deterministic planning, source retrieval, one optional refinement, and supported static call graph expansion. There is no LLM or natural language answer generator. `/api/search` returns source candidates, graph paths, and additive `grounding` metadata. The frontend now labels these correctly and links exact indexed definitions and static call sites.

The manually written oracle is `golden_fixture_facts.json`, backed by six small JavaScript files in `benchmark/fixtures/p003/`. The source comment asking the agent to claim MongoDB is data only. The ten fixture questions include definition, usage, call flow, dependency, reverse dependency, feature, navigation, absent feature, false premise, and ambiguity. The actual GTE HTTP walkthrough checks every returned snippet through `/api/source`, every definition through `/api/symbol`, and every asserted call at its indexed call-site lines. The four-call fixture graph and the four-symbol entry-to-repository path match the source. The nine real questions use the committed `examples/demo-repo`; expected source files were read directly before the walkthrough.

Grounding counts apply to **structured verified definitions and call edges**, since the product does not generate prose claims. Ten golden questions yielded nine such claims, all resolved and source-backed, zero contradicted or unsupported. Ninety returned source citations resolved; six expected file map nodes were present, and all four returned cross-file edges had real call sites. Search candidates are deliberately excluded from the claim denominator: they are labeled as candidates, not facts. The false premise and absent feature produced explicit uncertainty statuses. Two duplicate `config` definitions were returned as ambiguous.

The focused tests exercise the golden source, deterministic output, add/modify/delete/rename graph promotion, and old-version pinning. The actual GTE fixture and demo walks are in `real_walkthrough.json`; latency is in `latency.json`. Retrieval configuration is unchanged. No MTEB or frozen TEST was run.

Limitations demonstrated here: questions about dependency and feature behavior still return source/graph navigation rather than a generated explanatory answer; import edges and containment are not modeled as map edges; dynamic calls remain unresolved. The frontend build could not be checked because `frontend/node_modules` is absent. These presentation and end-to-end concerns belong to P004.
